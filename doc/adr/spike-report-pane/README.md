# Report pane spike

Evidence for the report surface chosen in
[ADR 0001](../0001-qt6-presentation-tier.md): a Qt 6 application hosts
`QWebEngineView`, loads an HTML document, and reads the rendered result back.

The question is deliberately narrow — can the pane work headlessly in CI and on
a build machine? — because the renderer choice itself was made in 0001.

## What is and is not Guile-produced here

The document fed to the pane is generated by a **plain Guile process**, not by
GnuCash's report engine:

```sh
guile -c '(display "<!DOCTYPE html>...")' > report.html
```

That proves the transfer path — a document produced outside Qt, rendered inside
it, and read back — but it does **not** prove that `(gnucash report)` output
renders correctly. Wiring the report engine is the next step and needs the
Scheme report modules built (`cmake --build <build> --target scm-report`).

## Running it

```sh
cmake -S . -B <build> -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build <build>
QT_QPA_PLATFORM=offscreen \
QTWEBENGINE_DISABLE_SANDBOX=1 \
QTWEBENGINE_CHROMIUM_FLAGS="--no-sandbox --disable-gpu" \
  <build>/spike-report report.html
```

The offscreen platform and the sandbox flags are what make this runnable without
a display; without them WebEngine wants a Chromium sandbox and a window.

## Expected output

```
load ok=1 input_bytes=193 rendered_bytes=192
```

exit 0. Last observed on Ubuntu 24.04 with Qt 6.4.2 WebEngine.

The byte counts differ by one because WebEngine normalises the document; compare
them loosely, assert on the exit status.

## Not verified

- HTML produced by GnuCash's own report engine (see above).
- Windows: `mingw-w64-x86_64-qt6-webengine` was not installed, and the
  Windows toolchain still lacks Guile, so the report side cannot be exercised
  there yet.
- CI: no workflow runs this spike.
