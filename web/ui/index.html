      Build a report from the same query, columns and options the native reports use. The preview beside the form is the report itself; save it under a name and it joins the list on the left. Saved reports live on the server (outside the book).

      What the report's rows come from. Choosing a source shows only the fields it accepts and clears the ones it does not: the server refuses a field of another source by name, so the form never sends one.

      Comma or space separated lowercase slugs: letters, digits and hyphens, at most 24 characters and 12 tags. Tags are saved with the report on the server, so every browser on this book sees them; click a tag in the Reports list to filter by it.

      The listing's columns, in print order. The flat split list and the grouped listings (the Transaction Report, the General Ledger and the General Journal) draw these from the same vocabulary.

      A flat list prints one row per split; by account, by account code and by transaction add that listing's sections and headings. A transaction-grouped listing is the General Journal's whole book, so it has no dates and no account selection.

      A flat list prints one row per account; the account tree rolls parents up and adds a subtotal; by period prints one row per year or month in the date range.

      Period activity is the amount earned or spent in each period. Balance at period end accumulates from the start of the book, which is what a net-worth or balance-sheet trend needs.

      Each checked account means that account and its whole subtree. Nothing checked means every account in the book.

      Restrict the report to these account types. This survives a different book, unlike an account GUID. Nothing ticked means every type; when both accounts and types are chosen, an account must match both.

      Which aging report: every A/Receivable or every A/Payable account in the book. The report ages every one of them, so it has no account selection.

      One row per owner is the aging report's own table; one row per document lists the invoices, credit notes, bills and payments whose amounts make the buckets.

      The report's Due or Post Date option: which invoice date decides the bucket a document falls into.

      The Lot Viewer's Account option: one account, whose own splits are listed. No account is the report's unset value, the whole book.

      The Lot Viewer's Description Filter: only transactions whose description contains this text. Empty lists every transaction in the period.

      The document report to print: a printable, easy or fancy invoice, a receipt, or one of the two tax invoices.

      The invoice, bill or voucher to print, by id or GUID. Empty prints the report's own 'no invoice selected' page.

      The document report's own print options. A value left at its default is not sent, so the report's own default document prints; a name the report does not publish is refused by the server by name.

      One or two amount columns the chart plots over the table's rows, or all three on a period report: debit, credit and balance are that period's two sides and its net (income, expense and net profit; assets, liabilities and net worth). Balance cannot be combined with just one side. Nothing ticked means the columns shown decide: debit and credit when both are shown, otherwise the balance or the one amount column.

      About GnuCash Web

      gnc-webd, the web tier of GnuCash. The engine is the same one the desktop application uses.

      The session's read or write mode is published by the server.

      Version: not published by this server

      The desktop's About shows the application version and build ID, which it reads from its build (gnc-main-window.cpp:5548-5551). gnc-webd publishes neither, so this dialog says so instead of printing a number the page would have to guess. The report store's version is shown when the server reports it.
